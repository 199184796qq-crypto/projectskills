# 版本与存档规范

## 先确定版本管理模式

项目启动时先确认以下其中一种模式，并写入项目硬性规则：

1. **本地版本库：** 按下文目录建立快照、索引和变更日志；不进行 Git 提交或推送。
2. **Git 即时同步：** 每次可追溯修改后，检查差异，仅暂存本次相关文件，提交并推送当前分支。Git 历史是主要回退来源；已存在的本地版本库仅保留，不删除。
3. **Git 阶段同步：** 在用户指定的一场或一集等短阶段内使用本地快照；阶段结束时，把该阶段内容、索引与说明一起提交并推送。未指定阶段范围时先询问。

所有 Git 模式均禁止强制推送、重写历史、硬重置或将无关用户改动提交。同步失败时保留本地状态，报告失败原因。

## 保存和恢复动作

1. 复制当前完整内容到新的版本文件，不重写旧版本。
2. 写入准确的版本文件头、版本历史和总变更日志。
3. 将索引中的“当前版本”指向新文件。
4. 用户确认后，再同步该版本内容到 `正式稿/`。
5. 恢复旧版本时，只更新索引和恢复记录；不删除后续版本，也不篡改其内容。
