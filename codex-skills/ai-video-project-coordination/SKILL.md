# AI 视频项目统筹

将异地团队的实际协作落到一个清晰的事实源结构：飞书管任务状态和审核，Git 管规则与轻量文本版本，百度网盘管大媒体文件；每位成员使用自己的 Codex 完成本地岗位工作。

## 启动或接手项目

先确认项目 Git 仓库根目录或远程仓库，以及用户是否希望本次创建/修改并推送仓库文件。若用户已给出仓库并要求初始化，可将该仓库视为项目根目录；先检查已有结构，绝不覆盖现有规则、剧本或资产。

读取 [协作操作模型](references/operating-model.md) 后：

1. 在 Git 中建立或核查项目总规则、当前版本索引、项目硬性规则、岗位职责、岗位技能及任务/问题/变更模板。
2. 只将规则、剧本、分镜、提示词、资产清单、剪辑清单和版本记录提交到 Git；大媒体文件必须排除在仓库外。
3. 为飞书任务表和百度网盘提供可直接建立的字段、状态、目录与交接要求，但除非用户已授权并提供访问条件，不擅自操作第三方系统。
4. 首次项目初始化后，在版本索引中明确哪些故事、角色、风格、模型和素材规则仍待确认，避免把未经锁定的内容交给下游生产。

## Codex 岗位助手模型

根目录 `AGENTS.md` 是所有 Codex 的共同流程；`roles/` 说明岗位边界；`skills/<岗位>/SKILL.md` 说明可复用的岗位方法。每个岗位任务开始时，Codex 必须依序读取：

1. `AGENTS.md`；
2. `剧本/项目硬性规则.md` 和当前版本索引；
3. 对应 `roles/<岗位>.md` 与 `skills/<岗位>/SKILL.md`；
4. 飞书任务卡中明确的 Git 输入版本和已授权/已下载的网盘资产。

不要把“今天做什么”写进 `AGENTS.md` 或岗位技能。动态工作始终由飞书任务卡分派。Codex 不能仅凭规则自动登录或读取飞书、百度网盘；需要由成员提供任务内容、授权连接，或先下载资产到本地。

## 任务、交付与变更

任务只有在输入版本、资产链接、交付目录、审核人都齐备后才能标记为“可执行”。岗位成员领取后改为“制作中”，完成后将文本提交 Git、大文件上传网盘，并在飞书转为“待审核”。

发现问题时，不让下游悄悄修改上游：

- 缺输入或横向协作，创建问题单。
- 发现剧情、分镜、设定或锁定资产有设计问题，创建变更单，列明影响范围和返工成本。
- 只有决策人批准后才产生新上游版本，并将受影响下游任务标为“需复核”或“已失效”。

## 默认岗位

默认建立编剧、分镜、素材、视频生成、剪辑包装五类岗位。用户要求新增、合并或拆分岗位时，同步更新岗位职责、岗位技能、`AGENTS.md` 路由表、任务表中的岗位选项和审核人设置。

## 完成标准

交付项目统筹基础设施时，报告：Git 项目规则与版本索引的位置、每个岗位的技能位置、飞书需要建立的表与视图、百度网盘需要建立的目录，以及仍需用户确认的创作规则。推送远程仓库属于外部写入；仅在用户明确要求或已将仓库交给本次初始化时执行。
