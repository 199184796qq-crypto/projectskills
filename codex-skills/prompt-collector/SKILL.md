# 提示词收录

## 核心目标

把零散提示词沉淀成可检索、可复用、可继续扩充的案例库。收录时保留原文和硬性要求，不把不同用途的案例堆在同一层级。

## 标准流程

1. 读取 `references/prompt-library.md`，先检索是否已有相同或高度相似案例。
2. 判断案例所属的一级分类和二级分类。
3. 保留原始提示词，不删除用户指定的名词、模型、时长、比例、声音、负面约束和输出格式。
4. 提取适用场景、标签、触发词、变量位、外部素材和注意事项。
5. 仅在确有必要时增加优化版；原始版必须保留。
6. 相同目的、相同结构的案例优先合并；仅是主体或场景不同，不重复建立案例。
7. 写入正确分类后，检查标题层级、编号和检索关键词。

## 案例库目录规则

案例统一保存在 `references/prompt-library.md`。使用固定层级：

```markdown
## 一级分类
### 二级分类
#### 编号. 案例名称
```

禁止把案例直接堆在文件根目录，也禁止使用“AI视频提示词”这类过宽分类承载所有内容。

### 一级分类

- `电商案例`
  - 产品广告
  - 带货口播
  - 产品展示
  - 食品试吃
  - 价格与促销
- `拍摄案例`
  - 运镜设计
  - 镜头与分镜
  - 构图设计
  - 灯光与画质
  - 人物表演
- `剪辑案例`
  - 转场设计
  - 节奏与卡点
  - 动作匹配
  - 字幕与包装
  - 声音设计
- `视觉风格案例`
  - 电影风格
  - 商业广告风格
  - 纪实与生活感
  - 特定世界观
- `角色与资产案例`
  - 人物一致性
  - 产品一致性
  - 场景一致性
  - 参考素材替换
- `工作流与分析案例`
  - 视频生成流程
  - 连续性控制
  - 样片分析
  - 提示词诊断
- `文案案例`
  - 短视频口播
  - 电商销售文案
  - 标题与钩子
- `代码与自动化案例`
- `其他待归档`

### 分类原则

1. 优先按最终用途分类，不按“图像生成/视频生成”这种媒介大类分类。
2. 电商产品广告归入“电商案例”，即使它同时包含运镜和灯光。
3. 单纯讲镜头运动、机位、焦段或构图的案例归入“拍摄案例”。
4. 讲镜头之间衔接、切点、转场、节奏或包装的案例归入“剪辑案例”。
5. 一个案例只能有一个主分类；跨分类属性写入标签，不复制案例。
6. 暂时无法判断时放入“其他待归档”，并标记缺失信息。

## 案例格式

````markdown
#### 编号. 案例名称

- 类型：
- 适用场景：
- 标签：
- 可复用触发词：
- 实现条件：
- 实现步骤：
- 原始版：
```text
...
```
- 优化版：
```text
...
```
- 变量位：
- 外部关键素材：
- 使用建议：
- 注意事项：
````

没有“实现条件”或“实现步骤”的普通案例可以省略对应字段。原始提示词已经清晰可用时，可以省略优化版。

## 外部素材

依赖参考图、视频、产品、包装、人物、场景或首尾帧的案例，必须单独记录素材要求：

- 必需素材：缺失后无法忠实生成的素材。
- 可选素材：用于提高一致性或细节质量的素材。
- 素材作用：说明每份素材控制人物、产品、包装、动作、场景、风格、首帧或尾帧中的哪一项。

不要把素材要求隐藏在长提示词内部。

## 关键词与检索

每个案例至少记录：

- 核心名词
- 目标效果
- 制作环节
- 关键限制
- 用户可能使用的自然触发词

用户以后只描述效果时，先按一级分类缩小范围，再匹配标签和触发词。返回最接近的案例，并根据新主体或新场景替换变量。

## 去重规则

- 目的、结构和约束相同，仅主体不同：合并为一个模板。
- 同一种技巧的左右方向、快慢版本：保留一个主案例，用变量位控制。
- 原始版与优化版：放在同一案例内。
- 同名但用途不同：保留两个案例，并用具体标题区分。

## 优化规则

- 保留所有硬约束：时长、比例、分辨率、语言、模型版本、声音和禁用项。
- 保留用户指定名词，不擅自泛化。
- 将可替换内容改为 `{主体}`、`{场景}`、`{产品}`、`{时长}`、`{方向}` 等变量。
- 发现冲突时明确标注冲突点并给出干净版本。
- 信息不足时标记缺口，不凭空补充。

## 输出要求

完成收录或整理后，简要报告：

1. 新增或移动了哪些案例。
2. 归入了哪个一级分类和二级分类。
3. 合并或去除了哪些重复项。
4. 用户下次可用什么短句调用。

默认使用中文，输出简洁、可执行。
