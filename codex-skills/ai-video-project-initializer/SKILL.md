# AI 短剧项目初始化

此技能只由项目负责人或获授权的项目总控使用。目标不是生成一堆空目录，而是交付一个让新成员只给出 Git 地址、姓名、岗位和个人授权信息就能开始工作的项目底座。

开始前读取 [初始化契约](references/initialization-contract.md)。其中定义目录、飞书字段、网盘交付路线和个人接入包的最小内容。

## 先核对输入与权限

确认项目名称、Git 远端或本地路径、项目负责人、启用岗位、飞书管理员连接、百度网盘团队空间以及初始成员清单。成员可承担多个岗位，但每张任务只保留一个责任岗位和一位负责人。

只有在负责人明确授权后，才创建 Git 文件、飞书多维表格／字段／初始记录、网盘目录或推送远端。已有非空仓库先检查结构和未提交改动；不得用初始化覆盖现有剧本、资产或规则。缺少飞书或网盘权限时，先完成可离线的 Git 基础设施，并清楚列出待补授权项。

## 初始化顺序

1. **Git 是文本与规则事实源。** 建立项目根规则、版本索引、路线图、剧本／分镜／提示词／资产清单／剪辑清单目录、岗位职责、岗位技能、项目加入技能、任务／问题／变更模板与本地凭据忽略规则。大媒体、令牌和成员私人接入包绝不提交 Git。成员仅被邀请到该项目仓库，使用自己的 Git 账号；生产成员在任务分支提交并发起合并请求，项目负责人审核合并受保护的 `main`。
2. **飞书是任务状态事实源。** 创建项目／集数、任务、资产、问题与变更、版本索引、成员与岗位六张关联表及其视图。只有输入版本、媒体入口、个人盘交付目录、团队归档目标、审核人与归档管理员完整的任务才能标为“可执行”。
3. **网盘分两层。** 成员使用自己的 Access Token 和官方 MCP 上传到个人盘中转目录；团队空间只保存审核后由归档管理员导入并复核的正式媒体。不要把团队空间 URL 或 ID 当作 MCP 的上传路径。
4. **将能力随仓库交付。** 把项目共用的岗位技能、工具专属视频提示词生成／审核技能及项目加入技能放在仓库 `skills/`，并在 `AGENTS.md` 写清读取顺序。视频提示词总助手只做路由和门禁；模型专属技能负责生成与审核。
5. **生成个人接入包。** 对每一位成员按其姓名和允许岗位生成一份不含秘密的岗位接入 Markdown；实际飞书令牌、个人网盘令牌和私有链接通过受控渠道单独发送。成员多岗位时，同一接入包列出全部允许岗位，但其 Codex 必须分别读取对应职责／技能并逐张领取单一岗位任务。

## 完成门禁

初始化完成前逐项验证：Git 规则和模板可读、凭据文件被忽略、岗位路由可达、飞书任务字段和“我的可执行任务”视图存在、个人盘中转与团队空间归档目录已指定、成员接入包不含秘密。随后提交并推送 Git；在项目中枢记录已创建内容、待补授权项与首批待输入任务。

不要替成员登录其飞书或百度账号，不发放管理员密钥，不把个人盘交付当成团队空间正式资产，也不因为一个人兼任多个岗位跳过审核和归档门禁。
