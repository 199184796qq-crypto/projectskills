# 玩法模板库（图片驱动的通用创意模板）

五个已固化的玩法，用户上传一张形象照片后触发，各自的追问问题+创意公式如下。跟`h3-prompt-guide.md`/`seedance25-prompt-guide.md`的关系：这份文件是"业务层模板"，负责把用户的简单选择（性别/风格/目的地）翻译成一句完整的核心创意+分镜设计；具体怎么把这句创意套进H3或Seedance 2.5各自的公式，还是要回那两份方法论文件查（参考素材说明怎么写/画面过程说明怎么分段/有锁定无锁定判断等）。

## 共同底层设计（5个玩法都遵循）

- **图片的定位**：用户上传的形象照片 = @图片1，标注为**人物参考**（H3）/ **主体参考**（Seedance 2.5，属于"参考生视频"里的主体参考能力，不是首尾帧）。原因：首尾帧模式（H3的图生视频、Seedance的`content.role=first_frame`）会锁定输出宽高比，而这5个玩法大多需要多镜头快切/场景变化，不适合首尾帧模式，所以统一走"多模态参考融合/参考类无锁定"，只锁人物身份，不锁构图。**2026-08-08更新**：换装玩法之前考虑过在有第二张"换装后"参考图时改用首尾帧模式，EV反馈模型已迭代、不需要首尾帧那套锁宽高比的方案，统一用参考生视频（主体参考）就够，不管有没有第二张参考图都一样走这条路。
- **模式标注**：H3 = 多模态参考融合；Seedance 2.5 = 参考类·无锁定·主体参考
- **时长**：8-15秒（换装/旅行/穿越/时尚模特是用户定的范围；跑酷用户没给，沿用同一区间保持产品一致性）
- **人物身份不变，画面/服装/场景可以变**：套用H3踩坑表里"人物参考图不代表连服装也锁定"这条注意事项——每个模板里人物的脸/身份要通过@图片1锁定，但服装、场景、动作都是随创意变化的，画面过程说明里要写清楚"人物身份不变，仅XX变化"防止模型把服装变化误判成人物变化。
- **卡点/快切是这5个玩法的共同节奏语言**：可以直接复用H3案例库里"大字幕MV""轻悬疑犯罪片头"那套"贯穿全片分层规则"写法（尤其是"律动规则"段落：鼓点触发切镜/文字/动作），把"BGM卡点触发画面变化"当成默认的剪辑逻辑。
- **⚠️ 多场景快切类玩法（旅行Vlog/穿越Vlog/跑酷）的转场要设计成蒙太奇式连续镜头，不能写平铺直叙的硬切**（2026-08-08新增）：提示词里不要写"切到下一个场景"这种明确的cut，而是让镜头跟随人物持续移动，用下面两种手法之一在场景之间做无缝过渡，让整段视频读起来像一镜到底：
  1. **快速甩镜（whip pan）转场**：镜头跟随人物移动时突然急速横甩/纵甩，运动模糊覆盖画面瞬间，甩镜停止时场景已经切换到下一个地点。
  2. **遮挡物穿越转场**：人物在持续移动中经过一个环境里的遮挡物——建筑转角、柱子、行道树、路过的行人、门框、经过的车辆/载具——遮挡物短暂完全挡住镜头视野，遮挡消失的瞬间背景已经变成下一个场景。**人物的动作状态（走路的姿态/步伐节奏）在遮挡前后必须保持连贯，不能断裂**，这样才有"一镜到底"的错觉。遮挡物要挑跟当前场景合理的东西：现代都市用路过的公交车/建筑柱子；历史场景用城墙拐角/路过的行人/牌楼廊柱；未来/科幻场景用飘过的悬浮载具或全息广告牌柱；外星球用飘过的异形植物。

  **⚠️ 分段写法：用"镜N"编号，不写时长（2026-08-08最终定稿，覆盖之前"写时间戳/模糊时间锚点"的两版试验）**：EV 的经验判断——H3和Seedance 2.5都内置了"导演系统"，知道怎么按内容自己分配每个镜头该占多长，不需要人替它算秒数，只需要告诉它"这里切几个镜头来演"。这跟两份官方手册原文都吻合：H3的"画面过程说明"和Seedance 2.5的"具体情节描述"都明确写着"用时间戳或'镜头N'切分，均可"——镜头编号本来就是官方认可的替代方案，不是我们发明的偏门做法。**统一写法：`镜1：……；镜2：……；镜3：……`，完全不写秒数、不写"约几秒后/临近尾声"这类模糊时间提示，把节奏怎么分配交给模型自己判断。**每个"镜N"的描述文字里仍然要保留"镜头持续跟随/无缝承接上一镜/同一条跟拍延续"这类连贯性语言（呼应上面"蒙太奇转场"的要求），只是不再挂时间刻度。

  这两种手法跟H3案例库"多素材联合参考"一节里"咖啡到沙漠的转场融合"那个案例（一镜到底、靠材质相似性做无痕转场，"中间不要出现拼接"）是同一类目标的不同实现——都是让多个场景拼接起来读起来是连续的一条镜头，不是拼接感明显的硬切。**换装模板不适用这条**，换装的转场是另一套已验证的"提前持有目标服装→披衣遮挡"机制，性质不同（换装的遮挡动机来自人物自身动作，这条讲的是场景/环境提供的遮挡）。

## 1. 换装（卡点换装/Glow-up）

**触发问题（生成提示词前必须问）**：性别（男/女）+ 想要的风格（给几个选项帮用户想：性感/酷炫/古风/正装/街头/赛博朋克，也可以让用户自己描述）

**创意公式**：
- 核心创意：@图片1的人物从居家慵懒造型开始，随卡点音乐鼓点通过一次带动机的遮挡式转场，切换为{风格}造型并顺势进入一个匹配气质的动态场景，展示{男性写"帅气/冷峻"，女性写"性感/炫酷"，或按用户指定}的动作与气场，广告级换装大片质感
- **转场揭示的必须是一整套全新造型，不是叠穿/加一件外套**：揭示的要是从头到脚一套完整、独立的新look（发型/上衣/下装/配饰整体换一遍），不能只是"在原有造型基础上加一件外套/多一条围巾"。
- **⚠️ 强对比原则（比转场机关本身更影响传播效果）**：开场造型和换装后造型的"能量反差"要尽量大——开场越平淡/低调/慵懒，换装后越炫（高能量、耀眼、有气场），加上揭示后场景从室内静止切到室外/动态大场景，反差会被放大两层，效果更抓人。别把开场造型设计得也很讲究，那样反差就弱了。
- 这个模板之前有一个验证过的完整范例可以参考结构（15秒，快速踩点，黑色高定连衣裙→亮银色金属感短裙），但**转场手法已按下面的新范式修正，不要再用旧版的"抓向镜头"式遮挡**。

**推荐默认范式（2026-08-08修正）：提前持有目标服装 → 转身披衣遮挡 → 揭示进入动态场景**

1. **开场铺垫**：人物居家慵懒造型（睡衣/家居服，刚起床的感觉，头发略乱，神情放松），**手上已经拿着待会要换上的{风格}衣服/外套**——这个细节要在开场就交代清楚，是后面遮挡动作成立的关键铺垫，不能等到转场那一刻才凭空出现衣服。
2. **转场（唯一一次）**：人物转身，双手展开手里拿着的衣服往身上披/穿，衣服在展开、挥动、套上的过程中自然地大幅度掠过并短暂遮挡整个镜头——这是"披衣"这个动作本身的自然副产品，不是额外加的孤立遮挡动作。
3. **揭示+动态场景**：遮挡移开的瞬间，人物已经完整穿好这套新造型（从头到脚一整套），紧接着**顺势带入一个匹配这套造型气质的动态场景/大动作**，不要只是原地摆pose——比如骑在摩托车上飞驰、走在山顶俯瞰、在街头跳街舞。**这几个只是举例，实际设计要按用户选的风格自己发散想新的场景/动作，不要局限在这几个例子里**：偏机能暗黑风可以配骑摩托/雨夜街头；偏运动帅气风可以配跑酷/篮球场扣篮前的助跑；偏复古绅士风可以配走下老爷车/推开酒吧门；偏赛博朋克风可以配霓虹街道漫步/操控全息屏幕。核心原则是"动态场景要跟换装后的造型气质匹配，且比开场更有视觉冲击力"。

**结构（一整条视频只有一次转场/一次换装，不要设计第二次）**：8-15秒大致分配为"开场铺垫2-4秒（居家造型+手持衣服）→ 转场披衣遮挡约1秒 → 揭示新造型+动态场景占据剩余时长"。换装视频的重点是把"变身瞬间"和"新造型的动态呈现"拍得有说服力，不是比谁换得多，全片只换一次。

**⚠️ 转场瞬间人物身体动作要合理，别让"姿态剧变"和"服装剧变"叠加到失控**：披衣动作本身有一定幅度是自然的（转身+展开衣服），但不要在同一瞬间又加别的大动作（比如同时还要求人物跳起来），把"大动作"分配给转场后的动态场景部分（骑摩托/跳街舞等），转场那一刻只做"转身+披衣"这一件事就够。

**如果这个默认范式不适合当次场景，也可以换用其他遮挡动机**（启发用，不限于此，实际设计时按场景自己发散）：甩手臂套进袖子、拉起衣领/拉链到脸部高度、弯腰捡起地上的衣物再起身、推开衣柜门/浴室门、被一阵风吹起的衣角、烟雾/蒸汽/水花/粒子特效等自然运动元素——但默认优先用"提前持有目标服装"这个范式，因为铺垫最清楚、遮挡动机最直给，且能自然带出后续的场景/动作升级。

## 2. 旅行Vlog

**触发问题**：去哪里旅游（具体城市/地区）

**⚠️ 生成前必须核实真实地标——这条不是"质疑用户陈述"，是履行内容准确性责任**：目的地一旦确定，需要给出2-4个真实、准确的当地标志性景点（参考用户给的示范：去福州→三坊七巷/乌塔/白塔/鼓山）。如果对该城市的地标不是很确定，**先用WebSearch核实**，不要凭印象编——编错地标名字，视频模型也生成不出真实的画面，等于白写。常见/知名城市（北京、上海、成都、福州等）如果确实有把握可以不查，拿不准就查。

**创意公式**：
- 核心创意：@图片1的人物在{城市}旅行vlog，8-15秒内一镜到底般跟拍经过{地标1}/{地标2}/{地标3}，每到一个地标妆造也随之换一套，充满活力的旅拍质感
- 结构：整段视频设计成镜头跟随人物持续移动的一条连续跟拍，**不是分开的独立镜头硬切**——每两个地标之间用甩镜或环境遮挡物（穿过牌坊/桥洞/路过的人群或车辆/树影）做转场，**遮挡消失后场景切换到下一个地标的同时，人物也已经换上一套新的完整妆造**（符合H3案例库和换装模板的规则：一整套完整look，不是叠穿加件外套），人物走路的姿态和节奏在遮挡前后保持连贯；每套妆造要跟当地气候/场景气质匹配（比如沙漠地标穿轻便亚麻装配头巾防沙，江南水乡换棉麻裙/衬衫，雪山换厚外套）；人物在每个地标前有一个自然的旅拍动作（拍照/张望/微笑转身/走动），8-15秒可以塞3-4个地标；结尾可以是对镜头笑/挥手的定格镜头
- 音乐/节奏：不用像换装那样强调鼓点卡点，更适合轻快的旅拍BGM，运镜节奏比换装柔和一点

## 3. 穿越Vlog

**触发问题**：穿越到哪里/哪个时代（历史朝代、奇幻世界、未来科幻场景、外星球都算——比如"中欧"指中世纪欧洲，"古代中国"指某个朝代，"赛博朋克未来都市""外星球"都可以）

**跟旅行Vlog的区别**：旅行Vlog是当代真实地标（需要核实真实性），穿越Vlog是历史/奇幻/科幻设定（不用核实"真实性"，但要合理设计该时代/世界观下有代表性的场景元素）：
- 中世纪欧洲：城堡、石板路、骑士盔甲、教堂尖顶、市集
- 古代中国（具体朝代按用户说的定）：对应朝代的建筑/服饰特征
- 赛博朋克未来都市：霓虹灯、悬浮载具、全息广告牌、雨夜街道
- 外星球：陌生地貌、异色天空、悬浮建筑或飞船、非地球植被

**创意公式**：
- 核心创意：@图片1的人物身处{目的地/时代}，8-15秒一镜到底般跟拍展示该时空的代表性场景，每次转场妆造也随场景一起换一套（发型/服装/配饰整体换，不是叠穿），自然融入该时代/世界观
- **只呈现穿越之后的结果，不要拍穿越的过程**：不要写传送门/时空裂缝/光效闪烁这类转场镜头，直接从目的地场景开始，就像人物本来就在那里拍Vlog
- 结构：开场即进入目标时空的第一个场景，整段设计成镜头跟随人物持续移动的连续跟拍，**不是分开的独立镜头硬切**——场景之间用甩镜或该时空里合理的环境遮挡物做转场（中世纪欧洲：城墙拐角/路过的骑士或村民/市集布幔；古代中国：牌楼廊柱/路过的行人；赛博朋克未来都市：飘过的悬浮载具/全息广告牌柱；外星球：飘过的异形植物/悬浮建筑结构），**遮挡消失后场景切换到下一个场景的同时，人物也已经换上一套符合该场景的新妆造**，人物走动的姿态和节奏保持连贯；8-15秒内可以塞2-4个该时空的代表性场景，每个场景里人物有自然的互动动作（就像旅行Vlog里"张望/微笑"那样，只是背景换成了穿越目的地），结尾可以定格在人物的一个自然表情或动作上（不需要呼应"穿越"这件事本身，当作这就是人物的日常场景来拍）

## 4. 时尚模特（直接抄H3案例库现成范例）

**触发问题**：性别 + 风格

**这个模板不用自己现场编创意，直接从`h3-prompt-guide.md`案例库里挑一个改**：
- 用户偏好"高级/冷感/极简"风格 → 抄**"时尚眼镜广告（白棚）"**案例结构：极简白棚无缝背景，高定广告感，把案例里的模特替换成@图片1的人物，服装/配饰按用户描述调整
- 用户偏好"复古/胶片/街头"风格 → 抄**"VHS故障风时装短片"**案例结构：胶片颗粒+VHS故障+90年代模拟质感，同样把模特换成@图片1
- 两个案例的完整提示词原文见`h3-prompt-guide.md`"产品与电商营销"和"品牌大片与影视内容"两节，改写时保留其运镜/氛围/风格描述的骨架，只换人物指代（改成@图片1）和具体服装描述（按用户这次要的风格重写）

## 5. 跑酷（城市穿梭，蜘蛛侠感）

**触发问题**：无强制问题（可选追问城市风格：现代都市/赛博朋克/复古老城，不追问则默认现代高楼都市）

**⚠️ 不要写成cosplay蜘蛛侠**：用户说"像蜘蛛侠那样"指的是**动作的流畅感和城市穿梭的张力**，不是要真的给人物穿蜘蛛侠服装或加超能力（除非用户明确要求）——写成"专业跑酷运动员般"的动作质感，别画蛇添足加蜘蛛网特效之类的版权/超能力元素。

**创意公式**：
- 核心创意：@图片1的人物以专业跑酷运动员的流畅动作在城市高楼间跳跃穿梭，动作干脆有张力，运动感强烈，{现代都市/赛博朋克/复古老城}背景
- 结构：整段设计成镜头跟随人物持续跑酷移动的连续跟拍，**不是分开的独立镜头硬切**——不同parkour动作段之间用甩镜或建筑元素做转场（贴墙翻滚经过一根柱子/穿过广告牌或天桥廊柱/绕过通风管道），遮挡消失后场景/角度已经切换到下一个动作段，人物的运动状态和速度在遮挡前后保持连贯；跟拍+俯拍/仰拍结合，展示翻越栏杆/跳跃楼顶间隙/攀爬/贴墙奔跑等parkour动作组合，关键跳跃瞬间可以用慢动作强调（H3/Seedance都支持"慢动作"这个运镜关键词直接写），结尾可以是站在高处俯瞰城市的收尾镜头

## 使用流程（跟主SKILL.md的衔接）

1. 判断用户的需求属于这5个模板里的哪一个（或者是自由创意，走主SKILL.md的通用流程）
