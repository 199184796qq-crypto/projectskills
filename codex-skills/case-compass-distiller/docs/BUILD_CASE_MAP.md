# 如何建立案例地图

## 案例数量

- 1—2 个：试用地图，只能近距离仿照结构；
- 3—12 个：标准起步区间；
- 13 个以上：建议按任务类型拆成多个邻域，避免所有案例互相干扰。

## 案例差异

不要只收十个几乎一样的成品。至少覆盖两种长度、两种难度或两类受众，系统才知道边界在哪里。

## 六个主要坐标

1. `domain`：领域，如 writing、video、design、analysis；
2. `job`：具体任务，如 opening、rewrite、outline；
3. `format`：载体，如 short_video、article、screenplay；
4. `audience`：受众；
5. `length`：大致长度；
6. `tone` 与 `constraints`：语气和硬限制。

## 结构路径

`path` 只记录该案例内部发生了什么。例如：

```json
["先抛异常结果", "补最少背景", "揭示真正冲突", "承诺后续答案"]
```

这不是全局规则，只是案例自己的路线。
